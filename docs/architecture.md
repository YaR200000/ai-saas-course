# Архітектура навчального Telegram-бота

## 1. Назва та мета продукту

**Назва:** Навчальний Telegram-бот на Python та aiogram.

**Мета:** Навчитися створювати, запускати та поступово розвивати IT-продукт, розуміючи призначення його основних архітектурних блоків: frontend, backend, database та API.

**Цільові користувачі:** Студенти-початківці, які вивчають Python, Telegram-ботів та основи розробки IT-продуктів.

### Поточні можливості

На цьому етапі в навчальному проєкті реалізовано:

- Команду `/start` для початку взаємодії з ботом.
- Команду `/help` для отримання довідкової інформації.
- Обробку повідомлень за допомогою Python та бібліотеки aiogram.
- Запуск застосунку в середовищі Docker.

Цей Telegram-бот є навчальним прикладом, на якому ми вивчаємо архітектуру IT-продукту. Підключення бази даних, AI-моделі та створення окремого вебінтерфейсу можуть бути наступними етапами розвитку.

## 2. Frontend — інтерфейс користувача

Frontend — це частина IT-продукту, через яку користувач взаємодіє із системою: бачить інформацію, вводить дані, натискає кнопки та отримує результати.

У нашому навчальному проєкті роль frontend виконує готовий інтерфейс месенджера Telegram.

### Як це працює

1. Користувач відкриває Telegram і знаходить нашого бота.
2. Вводить команду `/start` або `/help`.
3. Telegram передає повідомлення для обробки ботом через Telegram Bot API.
4. Після обробки команди користувач бачить відповідь у чаті Telegram.

### Що вже реалізовано

- Взаємодія користувача з ботом через Telegram.
- Введення команд `/start` та `/help`.
- Відображення відповідей бота в чаті.

### Що можна додати в майбутньому

- Інтерактивні кнопки та меню Telegram.
- Зручніші сценарії введення інформації.
- Окремий вебінтерфейс для майбутнього SaaS-продукту.

**Важливо:** ми не створювали власний frontend із нуля. Telegram надає готовий інтерфейс, а логіка обробки команд знаходиться в нашому Python-застосунку.

## 3. Backend — логіка застосунку

Backend — це частина IT-продукту, яка отримує запити користувачів, обробляє інформацію, виконує необхідні дії та формує відповіді.

У нашому навчальному Telegram-боті роль backend виконує Python-застосунок, створений із використанням бібліотеки aiogram.

Основна логіка бота знаходиться у файлі `app/main.py`.

### Як працює Backend

1. Користувач надсилає команду через Telegram.
2. Застосунок отримує інформацію про команду через Telegram Bot API.
3. Бібліотека aiogram визначає відповідний обробник команди.
4. Python-код виконує необхідну логіку та формує відповідь.
5. Бот надсилає відповідь через Telegram Bot API.
6. Користувач отримує повідомлення в Telegram.

### Що вже реалізовано

- Обробка команди `/start`.
- Обробка команди `/help`.
- Формування текстових відповідей користувачу.
- Логування подій та обробка окремих помилок застосунку.

### Що можна додати в майбутньому

- Обробку складніших запитів користувачів.
- Роботу з базою даних для збереження інформації.
- Інтеграцію AI-моделі для аналізу запитів та формування рекомендацій.
- Додаткову бізнес-логіку для майбутнього SaaS-продукту.

### Роль Docker

Docker використовується як середовище запуску нашого Python-застосунку.

Він допомагає запускати бот у контейнері з необхідними залежностями та налаштуваннями.

**Важливо:** Docker не є frontend, backend, API або базою даних. Це інструмент для запуску та організації роботи застосунку.

## 4. Database — база даних

Database (база даних) — це частина IT-продукту, яка відповідає за збереження, пошук, оновлення та отримання інформації.

База даних дозволяє застосунку зберігати інформацію між запусками та використовувати її для подальшої роботи.

### Поточний стан

У нашому навчальному Telegram-боті база даних поки що не підключена.

Наявні команди `/start` та `/help` формують текстові відповіді користувачу й не потребують збереження інформації в базі даних.

Тому на поточному етапі backend працює без окремого блоку Database.

### Які дані можна зберігати в майбутньому

Після підключення бази даних наш продукт зможе зберігати:

- Ідентифікатори користувачів Telegram.
- Налаштування та вподобання користувачів.
- Історію виконаних дій.
- Дані, які користувач вводить у боті.
- Результати обробки запитів та AI-аналізу.

### Як Database взаємодіятиме з Backend

1. Користувач надсилає команду через Telegram.
2. Backend отримує та перевіряє запит.
3. Якщо для виконання команди потрібні дані, backend звертається до бази даних.
4. База даних зберігає нову інформацію або повертає раніше збережену.
5. Backend обробляє результат і формує відповідь.
6. Користувач отримує повідомлення через Telegram.

**Важливо:** база даних є запланованим компонентом нашого продукту. У межах домашнього завдання №5 ми лише описуємо її призначення, а не підключаємо до застосунку.

## 5. API — взаємодія між компонентами

API (Application Programming Interface) — це набір правил і механізмів, за допомогою яких різні програмні системи обмінюються запитами та відповідями.

У нашому навчальному Telegram-боті використовується Telegram Bot API.

Telegram Bot API забезпечує взаємодію між платформою Telegram та нашим Python-застосунком на aiogram.

### Як працює API в нашому проєкті

1. Користувач надсилає команду `/start` або `/help` у Telegram.
2. Telegram отримує повідомлення користувача.
3. Наш Python-застосунок отримує інформацію про повідомлення через Telegram Bot API.
4. Бібліотека aiogram передає повідомлення відповідному обробнику.
5. Backend формує текстову відповідь.
6. Бот надсилає відповідь через Telegram Bot API.
7. Telegram відображає її користувачу.

### Що вже реалізовано

- Взаємодія Python-застосунку з Telegram Bot API.
- Отримання команд користувачів.
- Надсилання текстових відповідей.
- Використання бібліотеки aiogram для роботи з Telegram Bot API.

### Що можна додати в майбутньому

- Інтеграцію зі сторонніми сервісами через їхні API.
- Підключення AI-моделі через відповідний API.
- Створення власного backend API для майбутнього вебзастосунку.

### Різниця між API та Backend

**Backend** виконує логіку застосунку: обробляє команди, перевіряє дані та формує результати.

**API** визначає спосіб обміну інформацією між системами.

**Важливо:** Telegram Bot API не є нашим backend. Він забезпечує взаємодію Telegram із Python-застосунком, у якому знаходиться логіка бота.

## 6. Схема потоку даних

Потік даних показує, як інформація проходить між компонентами IT-продукту від моменту дії користувача до отримання результату.

### Поточна архітектура Telegram-бота

У нашому навчальному проєкті команди `/start` та `/help` не потребують бази даних.

```text
Користувач
    |
    v
Telegram (Frontend)
    |
    v
Telegram Bot API
    |
    v
Python / aiogram (Backend)
    |
    v
Формування відповіді
    |
    v
Telegram Bot API
    |
    v
Telegram -> Користувач
```

### Майбутня архітектура з базою даних

Після підключення бази даних потік інформації для функцій, які потребують збереження або отримання даних, може виглядати так:

```text
Користувач
    |
    v
Telegram (Frontend)
    |
    v
Telegram Bot API
    |
    v
Python / aiogram (Backend)
    |
    v
Database (збереження або отримання даних)
    |
    v
Python / aiogram (формування відповіді)
    |
    v
Telegram Bot API
    |
    v
Telegram -> Користувач
```

**Важливо:** друга схема показує запланований розвиток продукту. Наразі база даних у нашому Telegram-боті не використовується.

## 7. Приклад роботи команди `/start`

Команда `/start` — це приклад взаємодії користувача з нашим навчальним Telegram-ботом.

Вона демонструє, як frontend, API та backend працюють разом для обробки запиту й повернення відповіді.

### Послідовність виконання

1. **Користувач:** відкриває чат із ботом у Telegram і надсилає команду `/start`.
2. **Frontend (Telegram):** приймає введену команду та відображає повідомлення в чаті.
3. **API (Telegram Bot API):** забезпечує передачу інформації про команду до Python-застосунку.
4. **Backend (Python/aiogram):** отримує повідомлення та визначає обробник команди `/start`.
5. **Логіка застосунку:** формує текстову відповідь користувачу.
6. **API (Telegram Bot API):** забезпечує надсилання відповіді від бота до Telegram.
7. **Frontend (Telegram):** показує відповідь користувачу.

### Які архітектурні блоки беруть участь

- **Frontend:** Telegram — інтерфейс взаємодії з користувачем.
- **API:** Telegram Bot API — канал обміну інформацією.
- **Backend:** Python та aiogram — обробка команди й формування відповіді.
- **Database:** не використовується, оскільки команда `/start` не потребує збереження інформації.
- **AI-модель:** не використовується для виконання цієї команди.

### Результат

Користувач отримує текстове повідомлення від Telegram-бота.

Цей приклад показує, що навіть проста команда потребує взаємодії кількох архітектурних блоків.

**Важливо:** для виконання команди `/start` не потрібно підключати базу даних або AI-модель.

## 8. Приклади функцій реальних IT-продуктів

Щоб краще зрозуміти архітектуру IT-продуктів, розглянемо чотири функції популярних застосунків.

У кожному прикладі визначимо роль frontend, API, backend та database.

Наведені схеми є спрощеними навчальними моделями, а не точним описом внутрішньої інфраструктури компаній.

### Приклад №1. Telegram — надсилання повідомлення

**Функція:** користувач надсилає текстове повідомлення іншому користувачу.

- **Frontend:** інтерфейс Telegram, у якому користувач вводить текст і натискає кнопку надсилання.
- **API:** забезпечує взаємодію клієнтського застосунку із серверами Telegram.
- **Backend:** обробляє повідомлення, визначає отримувача та організовує доставлення.
- **Database:** забезпечує збереження необхідних даних повідомлень і чатів.

**Результат:** отримувач бачить повідомлення у своєму чаті.

### Приклад №2. Trello — створення картки завдання

**Функція:** користувач створює нову картку на дошці Trello.

- **Frontend:** інтерфейс дошки, у якому користувач вводить назву завдання.
- **API:** передає запит на створення картки до серверної частини.
- **Backend:** перевіряє запит, права доступу та виконує логіку створення картки.
- **Database:** зберігає інформацію про картку, дошку та її розташування.

**Результат:** нова картка відображається на дошці Trello.

### Приклад №3. Банківський застосунок — перегляд балансу

**Функція:** користувач відкриває застосунок і переглядає баланс свого рахунку.

- **Frontend:** мобільний інтерфейс, який відображає баланс.
- **API:** передає захищений запит до банківської серверної системи.
- **Backend:** перевіряє авторизацію та отримує актуальну інформацію про рахунок.
- **Database:** зберігає або надає необхідні фінансові дані через банківські системи.

**Результат:** користувач бачить доступний баланс рахунку.

### Приклад №4. ChatGPT — отримання відповіді на запит

**Функція:** користувач вводить запит і отримує відповідь AI-моделі.

- **Frontend:** інтерфейс ChatGPT, у якому користувач вводить запит і читає відповідь.
- **API:** забезпечує обмін даними між інтерфейсом та серверними компонентами.
- **Backend:** обробляє запит, організовує звернення до AI-моделі та повертає результат.
- **Database:** може використовуватися для збереження історії розмов, налаштувань та інших даних.
- **AI-модель:** генерує відповідь на запит користувача.

**Результат:** користувач отримує відповідь AI-моделі.

### Загальний висновок

У різних IT-продуктах архітектурні блоки виконують подібні функції:

- **Frontend** забезпечує взаємодію з користувачем.
- **API** організовує обмін даними між системами.
- **Backend** виконує логіку застосунку.
- **Database** забезпечує збереження й отримання даних.

Конкретна реалізація цих блоків залежить від призначення та складності продукту.
