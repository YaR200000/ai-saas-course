## Аудит і межі захисту

- FastAPI запускається з явним --host 127.0.0.1 та --no-proxy-headers.
  Middleware також перевіряє peer IP, локальний Host, збіг Origin з Host та
  Fetch Metadata. SQL-фільтр задає лише серверний API_ALLOWED_USER_ID.
- Vite dev/preview прив'язані до 127.0.0.1, strictPort увімкнено, CORS вимкнено.
  Його middleware перевіряє peer/Host/Origin/Fetch Metadata перед proxy.
  changeOrigin=false зберігає Host/Origin; це сумісно із FastAPI без послаблень.
- Frontend використовує лише відносні /api URL, не містить підключення до Neon.
  envDir=false вимикає завантаження env-файлів Vite. Секрети не потрібні браузеру.
- Перевірено весь поточний Git HEAD на типові формати токенів, приватних ключів
  та PostgreSQL URL із паролем: збігів не знайдено, значення не виводилися.
  Це обмежена перевірка шаблонів, не гарантія відсутності всіх видів секретів
  і не сканування всієї історії Git. Реальний .env не відкривався.
- .env/.env.* ігноруються, виняток .env.example містить лише приклади;
  node_modules, dist, .tools та логи також ігноруються й не відстежуються.

Обмеження: локальні процеси мають доступ без авторизації. SELECT у коді не
дорівнює обмеженням окремої read-only ролі PostgreSQL. Операції та summary —
окремі запити, тому при нових записах можливі різні snapshots і зміщення offset.
Не публікувати dashboard через тунель, зовнішню адресу або reverse proxy.
При відмові БД API повертає 503/no-store. При відсутньому backend Vite повертає
500; frontend показує контрольоване повідомлення й повторну спробу, не тіло помилки.
Фактична схема Neon та застосування попередньої міграції цим блоком не перевірені.

## Ручна перевірка: тільки після окремого погодження

Нижче інструкції для оператора; агент їх не виконував. Спершу підтвердити, що
попередня міграція погоджена й застосована, потрібні залежності встановлені,
локальний .env налаштований. Не виводити конфігурацію, токени чи персональні дані.
Не застосовувати міграцій у межах цієї інструкції. Відкрити три PowerShell-вікна.

### 1. Визначити користувача

У приватному Neon SQL Editor виконати лише SELECT, підставивши власний числовий
Telegram ID у себе локально (не пересилати його чи скриншот запиту):

```sql
SELECT id FROM users WHERE telegram_id = <ваш_числовий_Telegram_ID>;
```

Кутові дужки замінити числом. Результат має містити рівно один внутрішній id.
Не використовувати SELECT *, не виводити telegram_id або описи. Не вгадувати
власника за найменшим id: значення 1 у шаблоні не є налаштуванням реального доступу.
Якщо рядка немає, /start його не створить: користувача створює перша успішна
/expense. Це окрема погоджена операція запису, після якої потрібно повторити SELECT.

### 2. Вікно A — один Telegram-бот

Не запускати одночасно polling із Docker та локально. Якщо працює compose bot,
спершу зупинити його явно командою docker compose stop bot. Потім:

```powershell
Set-Location 'C:\Users\Шостак\ai-saas-course'
.\.venv\Scripts\python.exe -m app.main
```

### 3. Вікно B — FastAPI

```powershell
Set-Location 'C:\Users\Шостак\ai-saas-course'
$env:API_ALLOWED_USER_ID = Read-Host 'Перевірений внутрішній users.id'
.\.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000 --no-proxy-headers --env-file .env
```

Введений users.id є серверною конфігурацією тільки цього процесу. Він має
пріоритет над env-файлом. Не задавати його у frontend або параметрах URL.

### 4. Вікно C — React + Vite з переносним Node

```powershell
Set-Location 'C:\Users\Шостак\ai-saas-course'
$env:PATH = (Resolve-Path '.\.tools\node-v24.11.1-win-x64').Path + ';' + $env:PATH
Set-Location frontend
npm.cmd run dev
```

Відкрити http://127.0.0.1:5173. Якщо 5173/8000 зайнятий, визначити власника
процесу; не зупиняти чужі процеси і не перемикатися на зовнішню адресу.

### 5. Telegram → Neon → FastAPI → React

1. У своєму приватному чаті перевірити /start та /help. /start перевіряє SELECT 1,
   але сам по собі не підтверджує відповідність схеми для запису витрат.
2. Після окремого погодження записати одну витрату через /expense, наприклад
   `/expense 12.50 кава`, з власним дозволеним акаунтом. Це справжній запис
   фінансового обліку: використати реальну витрату або погоджене тестове середовище.
   Дочекатися підтвердження; не повторювати команду при неоднозначній помилці.
3. У dashboard натиснути «Оновити дані» на першій сторінці. Перевірити новий рядок,
   категорію, дату, витрати та відповідне зменшення балансу. Дохід залишається нулем.
4. У приватних DevTools → Network перевірити відносні /api/transactions та
   /api/summary, статус 200 та Cache-Control: no-store. Не експортувати HAR і не
   пересилати відповіді з фінансовими даними. За наявності понад 20 записів
   перевірити «Далі»/«Назад»; підсумки карток від цього не змінюються.
5. Тимчасово завершити лише FastAPI через Ctrl+C у вікні B. Оновити dashboard:
   має з'явитися повідомлення про недоступність. Повторно запустити ту саму команду
   FastAPI та натиснути «Спробувати ще раз». Не вимикати Neon заради перевірки 503:
   цей сценарій уже покритий ізольованим тестом.

### 6. Завершення

Ctrl+C у вікнах C, B та A, дочекатися повернення PowerShell prompt.
Бот/API закривають engine; Vite завершує dev-сервер. За потреби у вікні B:

```powershell
Remove-Item Env:API_ALLOWED_USER_ID
```

Закрити вікно C, щоб прибрати локальну зміну PATH. Якщо бот запускався тільки
через Docker, завершити його docker compose stop bot. Не відновлювати другий
polling-процес паралельно з першим. Результат ручної перевірки записати окремо
без токенів, персональних ідентифікаторів та описів приватних операцій.
