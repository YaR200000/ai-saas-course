# React Admin Dashboard — урок 7, блок 3

## Урок 8, блок D: видалення з підтвердженням

Потрібен backend із DELETE /api/transactions/{id}. Пароль і спільний pending
тепер живуть у App; POST/DELETE використовують один синхронний latch. Поля
створення залишаються у TransactionComposer, тому 401 очищає пароль без втрати
вводу. Вихід із режиму доступний лише коли адміністративний запит завершено.

Колонка «Дії» з'являється лише в адміністративному режимі. Кнопка відкриває
нативний dialog із типом, сумою, датою, категорією й описом. Фокус спочатку на
«Скасувати». Escape скасовує до запиту, Enter не підтверджує; для підтвердження
клавіатурою — Tab і пробіл. Під час запиту дії блоковані. Після закриття фокус
повертається до кнопки або заголовка таблиці, якщо рядок більше не доступний.

Клієнт зберігає ID як рядок, перевіряє BIGINT без Number, надсилає DELETE без
тіла, із credentials: omit та redirect: error. 204 не читається як JSON.
Після 204 повторюються один summary і потрібна сторінка таблиці. Останній
рядок непершої сторінки одразу переводить назад без GET відомо порожньої
сторінки. Якщо конкурентні зміни спорожнили іншу сторінку, додатково читається
лише попередня сторінка. POST як раніше повертає на першу сторінку.

401 скидає пароль і вибір операції — потрібне нове підтвердження. 404 оновлює
дані й повідомляє, що запис недоступний. 403/422 показують безпечні пояснення.
503 розрізняє вимкнений запис і непідтверджений результат. Мережеві помилки та
неочікувані відповіді не спричиняють retry. Після невідомого результату кнопки
видалення заблоковані до успішного нового GET списку; потім потрібне нове
підтвердження. Успіх DELETE не скасовується помилкою наступного GET.

Немає optimistic deletion, ручного розрахунку балансу, browser storage або
глобального Authorization. Backend, міграції та production Neon не змінюються.
Фізичне видалення Telegram-операції прибирає її ключ дедуплікації: старе
повідомлення при повторній обробці потенційно створить витрату знову.

Автотести на наявному Node runner перевіряють DELETE, межі BIGINT, статуси,
відсутність auth у GET, спільний latch, вибір сторінки, SSR діалогу/таблиці
й регресію POST. Без browser runner вручну на mock API або disposable БД
перевірити showModal/focus/Escape/Enter, 401 зі збереженням полів створення,
фактичну кількість GET, застарілі відповіді, невідомий результат, останню
сторінку та мобільне прокручування. Нові залежності не потрібні.

## Урок 8, блок C

Dashboard тепер показує доходи й витрати, календарну `date`, точні суми та
форму створення. Старий опис уроку 7 нижче є історичним: доходи вже підтримані.
Потрібен backend блоку B зі схемою після міграції 002; frontend міграцій не виконує.
Старий API без date відхиляється як несумісний. До робочої Neon не підключати
тестові створення: використовувати mock API або явно дозволену disposable БД.

У панелі введіть адміністративний пароль. Він перевіряється сервером лише
під час POST і зберігається лише у React state. Вихід із режиму або reload
очищає пароль; 401 також очищає його, зберігаючи введену операцію. Немає
storage, cookie, VITE_* або глобальних auth-заголовків. Пароль не входить у bundle.
Не експортувати HAR із Authorization. Браузерні розширення, менеджери паролів
і DevTools залишаються поза гарантіями пам'яті React. Це локальний навчальний UI.

Сума вводиться текстом із крапкою або комою, без float/округлення. Категорія й
опис проходять trim. Дата за замовчуванням — сьогодні у Europe/Kyiv; дата
операції відображається без зміни timezone, порядок записів визначає backend
за created_at. Пагінація — 20. Після 201 форма очищається, таблиця повертається
на першу сторінку, обидва GET повторюються. Баланс обчислює тільки backend.

401 просить новий пароль; 403 пояснює локальну відмову; 422 позначає поля;
503 розрізняє вимкнений запис і непідтверджене створення. Мережевий збій або
некоректна відповідь після POST можуть означати вже створений запис. POST
автоматично не повторюється: спершу перевірити список. Помилка GET після 201
не скасовує успіх POST і дає лише кнопку повторного читання.

Наявний Node test runner перевіряє клієнт, валідацію, календарні дати, SSR
стани, пагінацію, синхронний захист подвійного submit і справжній loopback proxy.
Без DOM/browser runner не доведені реальні кліки, state-переходи після 401,
оновлення React через effects після POST, focus і мобільна геометрія. Перевірити
їх вручну на ізольованих даних; нових залежностей цього блоку не додано.
DELETE та фільтри не реалізовані.

Потрібен Node.js 22.12+ або актуальний LTS та npm. З кореня репозиторію:

```powershell
cd frontend
npm install
npm run dev
```

Відкрити **http://127.0.0.1:5173**. Окремо з кореня запустити FastAPI за
інструкцією [API](../docs/transactions-api.md), вибравши перевірений внутрішній
API_ALLOWED_USER_ID. Frontend не читає backend .env: Vite envDir=false вимикає
завантаження env-файлів; секретна конфігурація для frontend не потрібна.

## Компоненти й дані

- `App.jsx`: оболонка, сторінка операцій, окремі повторні завантаження.
- `components.jsx`: SummaryCards, TransactionsTable та ErrorState.
- `useResource.js`: незалежні стани запитів, скасування при зміні сторінки або
  демонтуванні. Помилка одного endpoint не приховує дані іншого.
- `api.js`: тільки відносні `/api/summary` та `/api/transactions`, перевірка
  JSON-контрактів. Гроші форматуються без перетворення на float, ID — рядки.

Картки показують всі операції користувача, таблиця — по 20. Порядок залишається
таким, як повернув backend. Загальної кількості API не повертає: кнопка «Далі»
доступна для повної сторінки; після останньої повної сторінки може бути порожня
з можливістю повернутися. Зміни записів між запитами можуть зсувати offset.
Баланс розрахунковий: доходи поки не реєструються. Дати — Europe/Kyiv.
Є loading, error з повторною спробою та empty states; усі робочі дані тільки з API.

## Локальний proxy та безпека

Vite слухає 127.0.0.1:5173, strictPort не дозволяє непомітно змінити порт.
`/api` проксіюється на 127.0.0.1:8000 з `changeOrigin: false`: зберігаються
Host 127.0.0.1:5173 та браузерний Origin того самого frontend. Backend приймає
цей локальний Host і однаковий Origin; Fetch Metadata залишається same-origin,
TCP-клієнт backend — loopback. Не додаються X-Forwarded-* заголовки.
FastAPI змінювати не потрібно. Додатковий middleware Vite перевіряє loopback,
локальний Host, Origin та Fetch Metadata до proxy. CORS вимкнено.
Це локальний однокористувацький інтерфейс без авторизації; не публікувати через
тунель або reverse proxy. Інші локальні процеси мають доступ.

## Перевірки

```powershell
npm test
npm run build
npm run preview
```

Тести використовують Node test runner: контракти API-клієнта, форматування,
рендер компонентів через React SSR та справжній Vite proxy з ізольованим
HTTP-сервером. Дані у тестах — лише фікстури, вони не входять до робочого dashboard.
Тести не запускають FastAPI, не читають секрети й не підключаються до Neon.
`npm run preview` дозволяє локально переглянути dist з тим самим proxy;
це не production-сервер. Статична публікація dist без локального backend/proxy
не працюватиме. node_modules, dist, .tools та логи виключені з Git.

Блок 4: [інтеграційні докази, аудит та ручна перевірка для PowerShell](../docs/dashboard-verification.md).
Окремий інтеграційний набір запускається з кореня через
`python -B -m pytest tests/test_dashboard_integration.py -p no:cacheprovider -q`;
він використовує справжній FastAPI TestClient та ізольовану SQLite, без Neon.
